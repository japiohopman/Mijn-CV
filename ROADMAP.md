# 🗺️ Strategic Roadmap — Jaap Hopman Creative Developer Portfolio & CV

This is the strategic roadmap for `japiohopman/Mijn-CV`. It defines the long-term vision and structural progress for developing the portfolio from a CV site into a focused, high-impact professional creative developer portfolio.

> **Note on Orchestration:** Automated execution is managed via **GitHub Issues**, **Phase Branches** (`phase/<phase-id>-<short-name>`), and human-gated Phase PRs. See [`JULES_ORCHESTRATOR_V2.md`](./JULES_ORCHESTRATOR_V2.md) for execution details and state machine specifications.

---

## Strategic Goals

The site answers, within seconds:

1. **Who is Jaap?** — Creative Developer, Technologist, and former Chef.
2. **What does he build?** — Web applications, AI integrations, interactive simulations, and audio tools.
3. **What makes his background distinctive?** — Execution discipline, systems thinking, and adaptability bridged from professional kitchen leadership and music production into software engineering.
4. **What evidence exists that he can do it?** — Production codebases, live applications, interactive project demos, and technical architecture breakdowns.
5. **Why should a recruiter, client, or collaborator get in touch?** — Clear CTAs, frictionless contact forms, printable Kitchen CV, and interactive Portfolio Secretary.

## Strategic Phase Overview

### Phase 1 — Express & EJS Foundation (Complete)
- Express server architecture with modular EJS views and partials.
- Dedicated Kitchen CV route (`/keuken-cv`).
- Dual-theme support and interactive assets.

### Phase 2 — Positioning & Narrative (Complete)
- Core value proposition and message hierarchy.
- Confident hero copy, About narrative arc, and structured skills matrix.

### Phase 3 — Evidence & Projects (Complete)
- Reusable project card/detail structure highlighting technical depth.
- Direct links to promotional sites, Netlify apps, and GitHub repositories.

### Phase 4 — Conversion & Contact (Complete)
- Universal CTA strategy across hero, project transitions, and footer.
- Interactive contact form with honeypot spam protection and validation.

### Phase 5 — Visual System & UX (Complete)
- Reading rhythm and typography measure optimization.
- Interactive avatar cross-fade, gallery viewers, and mobile navigation drawer.

### Phase 6 — Technical Quality, Discoverability & Trust (Complete)
- OpenGraph/Twitter card metadata, Schema.org JSON-LD structured data, favicons, PWA webmanifest.
- Zero client-side tracking policy and privacy assertions.

### Phase 7 — Interactive Proof & Final Polish (Complete)
- Interactive dice rolling simulator (Artificer), live iframe embed (Global Conquest), and email classification pipeline simulator (SuperMail).
- Web Audio API synthesizer simulation and BPM beat engine in About section.

### Phase 8 — Portfolio Secretary: Product & Architecture (Complete)
- Deterministic UMD intent engine and canonical knowledge registry (`secretary_knowledge.json`).
- Dynamic tool call execution (`navigateToSection`, `openKitchenCV`, `openShare`, `openProject`).
- Accessible floating UI widget included across all public routes.

### Phase 9 — Optional LLM Adapter & Orchestrator v2 Architecture (Complete)
- Optional UMD LLM Adapter for natural language query parsing constrained strictly to canonical intent IDs and facts.
- Issue-driven Jules Orchestrator v2 supporting Phase Issues, Task Issues, dedicated Phase Branches, and human review gates (`JULES_ORCHESTRATOR_V2.md`).

### Phase 10 — Autonomous Jules Dispatch Validation (Active)
- End-to-end validation of issue-driven Jules automation with immediate issue-event triggering and dedicated phase branch (`phase/10-jules-dispatch-validation`).
- Automatic selection of Phase and Task issues, explicit specialist agent profile loading, session deduplication, and enforcement of human review gates.
